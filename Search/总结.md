# 搜索（Search）

---

## 一、内容

搜索就是把解空间看成一棵树或一张图，按某种顺序系统地走一遍，把答案找出来。

两条主线：

- **DFS（深度优先）**：一条路走到底，走不通再回头。用来**枚举所有方案、求方案数、找任意一个解**。核心是回溯——进入时标记，离开时取消。
- **BFS（宽度优先）**：一层一层往外扩。用来**求最少步数 / 最短距离**，第一次到达某个状态时就是最优。

复杂度一般是 **O(状态数 × 转移数)**。状态数很容易爆炸，所以**去重和剪枝是搜索题的生死线**。

常见的四种形态：

1. **网格上的连通块 / 最短路**——flood fill，BFS 或 DFS 都行；
2. **回溯枚举**——DFS + `path` 维护当前路径 + 标记/取消；
3. **状态空间搜索**——把字符串、集合本身看成状态，一步变换就是一条边，BFS 求最短；
4. **记忆化 / 状态压缩**——状态太多时压成 mask，这时本质上已经滑向 DP 了。

## 二、题目

1. **A - 初见可解**

   - P1596 [USACO10OCT] Lake Counting S
     - 遍历网格，遇到未访问的 `'W'` 就启动一次 BFS 淹掉整个连通块，池塘数 +1
     - 坑点：边界判断用 `< 0` / `>= n`，不是 `<= 0`；**入队时立刻标记 visited**；`pair` 第一个是行第二个是列，别写反

   - P1101 单词方阵
     - 遍历整个方阵，遇到 `'y'` 就朝 8 个方向连查 7 个字符是否拼成 `"yizhong"`
     - 坑点：单词之间会**交叉共用字母**，所以不要直接在原数组上改，另开 `keep` 数组记录归属，最后统一输出

   - P2404 自然数的拆分问题
     - DFS 回溯，用全局 `path` 维护当前序列，每次从 `last` 开始枚举下一个数以保证非递减，`sum == n` 时输出
     - 坑点：单个数字不算拆分，必须 `len > 1`；不限非递减会重复（1+2+1 与 1+1+2）；循环上限是 `n - sum` 不是 `n`；`path[len] = i` 写完下一轮循环覆盖它，相当于隐式回溯

2. **B - 初见难**

   - P1162 填涂颜色
     - 反向标记：从四条边界出发 BFS，把所有与边界相连的 0 标为"圈外"，剩下的 0 就一定是被 1 包围的圈内，输出时改成 2
     - 坑点：BFS 开头先查 `maze[x][y] == 1 || 已标记`，避免重复入队；下标从 0 开始读

   - P1135 奇怪的电梯
     - 马的遍历的翻版：把"上下左右跳马"换成"上下楼"，BFS 求最少按键次数
     - 坑点：楼层越界判断要在入队前完成

   - P1605 迷宫
     - 求的是**路径条数而不是最短路**，所以用 DFS 回溯：进入时标记、离开时取消，走到终点方案数 +1
     - 坑点：基 1

   - P1019 [NOIP 2000 提高组] 单词接龙
     - 先预处理出单词两两之间的**最短重叠长度**存成关系表，再从以给定字母开头的单词出发 DFS 接龙
     - 坑点：重叠取**最短**不是最长（龙才最长）；每个单词最多用两次要 `used[]` 计数；枚举重叠最大只到 `min(l1, l2) - 1`（不能有包含关系）；开头字母可能对应多个单词，每个都要当起点试一遍

3. **C - 复杂体**

   - P1443 马的遍历
     - BFS 求马到每个格子的最少步数，先走完这一层再往下走
     - 坑点：基 0 / 基 1；队列按坐标对开，容量要够

   - P1219 [USACO1.5] 八皇后 Checker Challenge
     - 一行一行往下放，放不下就回溯；用高度凝练的数据结构能省掉极多判断
     - 坑点：数据结构的选型；基 0 和基 1 的转换
     - 杂谈：这个数据结构，这个 DFS，太漂亮了。

   - P2392 kkksc03 考前临时抱佛脚
     - 分成左右脑两摞，对每一摞搜一次"不超过总和一半的最大值"，两边取较大者
     - 坑点：`dp[0]` 要置 1

   - P2895 [USACO08FEB] Meteor Shower S
     - **不要去模拟流星落地**：先预处理出每个格子最早被摧毁的时间 `destroy[][]`，再把这个时间当作 BFS 的约束条件
     - 坑点：BFS 的边界判断、位置判断，以及出队入队的时机

   - P1825 [USACO11OPEN] Corn Maze S
     - BFS + 传送：踩到滑梯端点立刻传到配对端点，距离只 +1（走上去那一步），传送本身不花时间
     - 关键设计：滑梯端点**本身不标记为已访问、也不入队**，只把配对点入队并标记——否则会堵死后续可能更短的路径
     - 坑点：跳过条件必须允许滑梯端点重复进入；`dist` 初始化为 -1；`'@'` 和 `'='` 不是障碍要单独处理；每个字母恰好出现两次

   - P1032 [NOIP 2002 提高组] 字串变换
     - 把每个字符串看成状态、一次变换看成一步，BFS 第一次遇到目标串时的步数就是最少步数
     - 坑点：规则数量不确定，用 `while (cin >> a >> b)` 读到 EOF；一次只替换一个位置，同一子串出现多次要分别生成；**必须去重**（`unordered_set`）否则队列爆炸；`find` 返回 `size_t`，比较用 `string::npos`

   - P1433 吃奶酪
     - 状态压缩：`mask` 表示已吃奶酪集合，`dp[mask][i]` 表示吃完 mask 后停在第 i 块的最短距离
     - 坑点：`n = 0` 特判、浮点精度、INF 判断
     - 说明：严格讲这是状压 DP 不是搜索，当初是按"状态穷举"的思路做的，放在本专题作为对照

## 三、总结

1. 先判断求的是什么：求**最短 / 最少**用 BFS，求**方案数 / 所有方案**用 DFS 回溯；
2. DFS 的三件套——**进入时标记、递归、离开时取消**，忘了取消就全错，能按值传递就别用全局量；
3. BFS 的要点是**入队时立刻标记**，否则同一状态会被反复入队，队列直接爆炸；
4. 搜索题的瓶颈永远是状态数，去重（`visited` / `unordered_set`）和剪枝决定生死；
5. 网格题统一注意两点：边界判断用 `< 0` / `>= n`，基 0 还是基 1 **从头到尾保持一致**；
6. 当状态能被 mask / 二进制压缩时，其实已经从搜索滑向 DP 了，别硬搜。

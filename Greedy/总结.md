# 贪婪(Greedy)

---

## 一、内容

贪心就是每一步都做**当前看起来最优的选择**，不去考虑全局，指望局部最优累积成全局最优。

难点不在"怎么写"——贪心代码往往很短——而在"凭什么这样是对的"。贪心成立通常需要一个数学证明（邻项交换 / 交换论证），这一般会是一个数学问题了。~~（所以说计算机正统在数学）~~

复杂度上，决策本身通常是 O(1)，主要开销在**排序**上，一般是 O(N log N)；需要反复取最值的题则再加上堆的 O(log N)。

常见的三种套路：

1. **排序后按某个关键字贪心**——短作业优先、性价比优先、结束时间优先；
2. **双指针 / 两端配对**——排序后最大配最小，或从两端取更优的一端；
3. **每次取当前最优，合并后放回**——需要堆或有序链表维护，如 Huffman 式合并。

## 二、题目

1. **A - 初见可解**

   - P1223 排队接水
     - 短作业优先：按接水时间升序排队，总等待时间最小
     - 坑点：总等待最坏 5×10⁹，`int` 存不下要用 `long`；求平均要转 `(double)`，用 `float` 精度不够会导致四舍五入出错

   - P2240 【深基12.例1】部分背包问题
     - 按单位价值 `v/m` 降序，装得下就整取，装不下就取一部分
     - 坑点：`int/int` 得到的还是 int，要先 `(float)` 强转

   - P1478 陶陶摘苹果（升级版）
     - 先按高度筛掉够不到的（`x <= a+b`），剩下按所需力气升序摘
     - 坑点：一个都够不到 / 一个都摘不起时 `cnt = 0`，别越界

   - P1094 [NOIP 2007 普及组] 纪念品分组
     - 升序后双指针，最大的试配最小的，配不上就让最大的单走
     - 坑点：配对循环用 `while (left <= right)`，用 for 容易把两个指针的推进写乱

   - P4995 跳跳！
     - 升序后从两端往中间跳，每次选与当前高度**差更大**的那一端

   - P3817 小 A 的糖果
     - 相邻两盒和超上限时，**优先减右边那一盒**——它不会影响已经处理过的左边
     - 右边减到 0 还不够，再减左边

   - P5019 [NOIP 2018 提高组] 铺设道路
     - 把"区间整体下挖"拆成相邻的**高度差**：只要 `a[i] > a[i-1]`，答案就累加这个差值
     - 初见容易去一天天地模拟，想到差分视角才一行搞定

2. **B - 初见难**

   - P1106 删数问题
     - 删 k 位后剩余位数是固定的 → 由高到低每一位在自己的可选区间里挑最小的
     - 坑点：搜索右端要保证后面还选得够（`end = k + i`）；输出要去前导零，全零要输出一个 `0`

   - P1012 [NOIP 1998 提高组] 拼数
     - 不是比数字本身的大小，而是比**拼接结果**：`a+b > b+a` 则 a 在前
     - 坑点：`cmp` 里直接 `strcmp(ba, ab)` 就是降序，别写反

   - P1803 凌乱的yyy / 线段覆盖
     - 按**结束时间**升序，能接上就选
     - 证明：把首个活动换成结束更早的那个，结果不变还更宽松（详见文件头注释）

3. **C - 复杂体**

   - P1080 [NOIP 2012 提高组] 国王游戏
     - 结论：按左右手乘积 `L×R` **升序**排列时，最大奖励最小；完整邻项交换证明见 `证明.md`
     - 坑点：**高精度**，1000 个 10⁴ 相乘远超 `long long`，要自己写大整数乘除

   - P1090 [NOIP 2004 提高组] 合并果子
     - 每次取最小的两堆合并，代价累加；重点在"怎么快速拿到当前最小值"
     - 有序链表版 O(N²) 已完成；小根堆版 O(N log N) **待补**（`C.Combine Fruits-P1090-MinHeap.c` 已建未写）

   - P4447 [AHOI2018初中组] 分组
     - 降序扫描，每个数接在当前末尾比它大 1 的**最短**队伍后面，接不上就新开一队
     - 链表版已完成；堆版 **待补**（`C.Grouping-MinHeap-P4447.c` 已建未写）
     - 坑点：新建节点 `next` 要置空，链表用完要 `free`

## 三、总结

贪心的关键：

1. 先确认"局部最优能推出全局最优"，这需要证明，别靠感觉；
2. 找到**排序关键字**（时间、性价比、结束时间、拼接结果……）——大部分题排完序答案就出来了；
3. 想清楚每一步"选谁、丢谁"，尤其是会影响后续的选择（糖果优先减右边、删数的搜索区间）；
4. 需要反复取最值的，用堆（或有序链表）维护，不要每次重排；
5. 贪心题的坑大多在**边界和数值范围**上：爆 `int`、浮点精度、前导零、一个都选不了的情况。

# 二分（Binary）

---

## 一、内容

二分通常用于具有 **单调性** 或 **二段性** 的序列 / 答案空间：维护左右边界 `left`、`right`，取中点 `mid`，根据 `mid` 是否满足条件来收缩区间，直到区间收敛或达到所需精度。

二分查找的时间复杂度为 **O(log N)**；二分答案的复杂度通常为 **O(log(值域) × check)**，一般不用太担心。

常见的三种形态：

1. **二分下标**——在有序序列里找位置、找边界（第一个 ≥ x、最后一个 ≤ x）；
2. **二分答案**——答案不好直接求，但"给定 x 判断是否可行"很好写，于是二分这个 x，配 `check` + 贪心验证；
3. **浮点二分**——答案连续，按精度（或固定迭代次数）收敛，注意输出格式。

## 二、题目

1. **A - 初见可解**

   - P2249 【深基13.例1】查找
     - 最简单的二分，二分内容 / 上下界 / 条件全部给出
     - 坑点：基 0 与基 1 的转换；找到后要**继续二分**找最靠前的位置，而不是线性往前扫

   - P1102 A-B 数对
     - 排序后枚举 B，用 `B + C` 确定 A，再二分统计 A 出现的个数
     - 坑点：答案会超过 `int`，要用 `long`；也可以不用二分，双指针 O(N) 做（见文件末尾注释）

   - P2440 木材加工
     - 二分长度，算能切出的总段数，够了就记录并继续往大试
     - 坑点：`left` 不能取 0，会有除零错误；二分 + 扫描是 O(log n × n)，放心用

   - P1678 烦恼的高考志愿
     - 对每个分数二分找最接近的分数线，累加差值
     - 坑点：没命中时的边界——`right < 0`（比所有分数线都低）、`left >= m`（比所有都高）要单独判断

2. **B - 初见难**

   - P1873 [COCI 2011/2012 #5] EKO / 砍树
     - `left = 0`、`right = `最高树，直接二分高度，算能砍到的总长度
     - 坑点：数据范围大，累加量用 `long long`；`O(log N)` 真的很快，不用畏手畏脚

   - P2678 [NOIP 2015 提高组] 跳石头
     - 逆向：不直接求最短跳跃距离，而是假设一个 `d`，检查"移走 ≤ M 块石头能否让所有间距都 ≥ d"
     - 坑点：最后一块石头到终点的距离不够时，如果还能移，是**把最后一块石头移走**，而不是判成不合法

   - P1182 数列分段 Section II
     - 同样是逆向：假设每段和的上限为 `x`，检查能否分成 ≤ M 段
     - 坑点：`check` 里各种情况都要考虑到——单个数本身就超过 `x`、刚好分完、最后不够一段

   - P3853 [TJOI2007] 路标设置
     - 与跳石头几乎同一套：二分"最大相邻间距"，检查插入 K 个路标能否压到该间距以内
     - 有了跳石头的经验后基本没有新坑

   - P3743 小鸟的设备
     - 逆向 + 贪心 + **浮点**二分：假设能用 `t` 时间，检查"总充电量是否追得上总消耗量"
     - 坑点：输出要 `%.10lf`；切换不耗时且初始电量均大于 1，只关心总消耗与总充电的关系即可

## 三、总结

二分的关键在于：

1. 先判断有没有单调性 / 二段性；
2. 确定对什么二分：下标、答案，还是某个中间量；
3. 写出 `check(mid)`，并保证边界收缩正确——`left`/`right` 到底取 `mid` 还是 `mid ± 1`；
4. 整数二分与浮点二分的**终止条件和答案记录方式不同**，别混用；
5. 答案不好直接求时，反过来想"如果答案是 x，能不能验证"——这就是二分答案的入口；
6. 复杂度一般是 O(log(值域) × check)，胆子大一点，不用过度担心时间。

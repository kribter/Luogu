# 线性表（LinearList）

---

## 一、内容

栈、队列、链表都是**在数组/顺序结构上加了限制**的产物：限制越少越灵活，代价是定位变慢。

- **栈（stack）**：只允许在**顶端**操作，后进先出。用在"最近的一次需要配对/抵消"的地方——括号匹配、表达式求值、模拟"撤销"。
- **队列（queue）**：一端进一端出，先进先出。用在"按先后顺序处理"的地方——排队出圈、缓存淘汰、**滑动窗口**。
- **链表（list）**：任意位置插入删除都是 O(1)，前提是**你得先拿到那个位置的迭代器**；随机访问要 O(N)。

复杂度上，栈和队列的每次操作均摊 **O(1)**，`list` 的插入删除 O(1)，`unordered_map` 平均 O(1)。所以这一专题的题基本都是 **O(N)** 或 **O(N log N)**（带排序）。

常见的四条主线：

1. **纯模拟**——把题面流程翻译成"入 / 出 / 查"三种动作，然后照着跑（约瑟夫、机器翻译、验证栈序列）；
2. **栈做配对与求值**——遇到右半边就回头找最近的左半边（括号序列、后缀表达式）；
3. **队列做滑动窗口**——维护一段区间内的统计量，进队时更新，出队时回滚（海港）；
4. **稀疏 / 任意位置的增删**——下标范围很大但用得少用哈希，需要 O(1) 插删就用链表 + 迭代器（寄包柜、队列安排、营业额统计）。

## 二、题目

1. **A - 初见可解**

   - P3613 【深基15.例2】寄包柜
     - `vector<unordered_map<int, int>>`：外层 vector 按下标 O(1) 定位柜子，内层哈希只存真正用过的格子
     - 坑点：柜子编号从 1 开始，vector 要开 `n + 1`；**查询用 `find` 而不是 `[]`**，否则会往哈希表里插入默认值 0；没存过的格子输出 0

   - P1996 约瑟夫问题
     - `1~n` 依次入队，从队头取人报数，`id == m` 就出圈输出、**不再入队**，否则塞回队尾
     - 坑点：出圈后 `id` 要重置为 **0 而不是 1**；队列为空时结束

   - P1540 [NOIP 2010 提高组] 机器翻译
     - 队列模拟内存，`bool` 数组标记单词是否在内存中；不在就查词典次数 +1 并入队，超过 m 就弹队头**并取消标记**
     - 坑点：单词编号 ≤ 1000，**标记数组按值域开 1005，不是按 n 开**；判满用 `q.size() > m`；弹队头别忘取消标记

   - P4387 【深基15.习9】验证栈序列
     - 按出栈序列逐个匹配：按入栈顺序压栈，直到栈顶等于当前出栈元素才弹出；入栈序列用完仍匹配不上就是 No
     - 坑点：栈空时不能调 `top()`；入栈前检查 `j < n` 防止越界；**先读完整组数据再统一判断**，避免中途 `break` 影响输入

2. **B - 初见难**

   - P2058 [NOIP 2016 普及组] 海港
     - 队列存每艘船（到达时间 + 国籍列表）构成 24 小时滑动窗口，`unordered_map` 统计窗口内每个国籍的人数
     - 坑点：时间差**正好等于 86400 的要弹出**，用 `>=` 不是 `>`；国籍编号可能很大，用 `unordered_map` 而非固定数组；`sum` 只在人数 **0→1 时 +1、1→0 时 -1**

   - P1449 后缀表达式
     - 逐字符扫描：数字累积到 `num`，`.` 入栈并重置，`+ - * /` 弹两个数算完压回，`@` 结束，栈顶即答案
     - 坑点：操作数可能是多位数，必须 `num = num * 10 + (c - '0')` 累积；**先弹出的是右操作数**，减法和除法顺序别反；遇到 `.` 必须把 `num` 清零；`@` 要 `break`；表达式串内无空格

   - P1160 队列安排
     - `list` + `pos[]` 存每个同学的迭代器，插入删除都 O(1)：插左边 `insert(pos[k], i)`，插右边 `insert(next(pos[k]), i)`
     - 坑点：`insert` 是插在**给定位置之前**，所以插右边要 `next`；删除用 `removed[]` 标记防重复删除（迭代器失效）

   - P1241 括号序列
     - 栈存未匹配左括号的**下标**，遇到右括号看栈顶能否匹配，成功就把两处都标 `matched`；最后扫原串，已匹配原样输出，未匹配补另一半
     - 坑点：`matched[]` 必须初始化为 false；**栈空时不能调 `st.top()`**；未匹配的右括号补左括号，未匹配的左括号补右括号

3. **C - 复杂体**

   - P2234 [HNOI2002] 营业额统计
     - 排序后用**数组模拟双向链表**，`prev`/`next` 存排序后的下标；**从最后一天倒着处理**，此时当前节点的前驱和后继就是最接近的两个值，处理完把它从链表里摘掉
     - 为什么是 C：难点不在数据结构本身，而在"**倒着删**"这个视角——正着做就得每次找前驱后继，倒着做它们天然就在手边
     - 坑点：`prev`/`next` 存的是**排序后的下标**，容易和原始天数混淆；第 1 天直接加营业额不比较；结果可能超 `int`，用 `long long`

## 三、总结

1. 先看**操作被限制在哪**：只在顶端动 → 栈；两端 FIFO → 队列；要往中间插 → 链表。这一步想清楚，代码结构就定型了。
2. STL 的 `stack` / `queue` 是**容器适配器**，没有迭代器、不能遍历。需要遍历或者随机访问时改用 `deque` / `vector` 自己维护。
3. **模拟题先把流程翻译成"入 / 出 / 查"三种动作**再动手写代码，边读题边写最容易漏掉"取消标记""重置计数"这类收尾动作。
4. 凡是"下标范围很大但实际用不了多少"的场景，一律上**哈希稀疏存储**（`unordered_map`），别硬开数组。
5. 用 `list` 或链表时，脑子里始终要分清**迭代器**和**值**——存迭代器的数组只有在节点没被删时才有效。
6. 栈和队列的**每一次 `top()` / `pop()` / `front()` 前先看 `empty()`**，这是这一专题最常见的运行时崩溃来源。
7. 辅助数组按**值域**开还是按 **n** 开，动手前确认一次；计数类结果默认上 `long long`。
